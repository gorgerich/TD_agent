## 1. Что делает визуализатор атрибутики

На шаге «Атрибутика» в конфигураторе сметы показывается фотореалистичная сцена зала прощания: выбранный **гроб** лежит на катафалке (готовая AI-сцена-фон), а выбранные **венки** (до двух) накладываются сверху по центру левого и правого мольбертов. Прочие атрибуты (крест, постель, таблички) пока не композитятся в сцену.

### Поток данных (сцена)

```
EstimateItem[] (позиции сметы)
  → derivePreviewConfigFromEstimateItems()   [components/AttributeRender.tsx]
      определяет гроб/венки/крест по тексту позиции, мапит catalogItemId → SKU через SKU_LAYER
      возвращает AttributePreviewConfig { casketSku, wreathSku, wreathSkus[], crossSku, ... }
  → previewIdsFromConfig()                    [components/AttributeRender.tsx]
      { coffinId, wreathId, wreathIds[], crossId, upholsteryId }
  → <RitualSetPreview coffinId wreathIds ... variant="bare" />   [components/visualizer/RitualSetPreview.tsx]
      SceneStage: фон = /visualizer/scenes/<coffinId>.jpg
                  венки = /visualizer/wreaths-cut/<wreathId>.webp, позиция из карты якорей
```

- `SKU_LAYER` (в `AttributeRender.tsx`) строится из `AGENT_ATTRIBUTION_CATALOG`: `id → basename(imageUrl)`. Именно basename = имя файла сцены/выреза.
- `AttributePreviewConfig` объявлен в `components/funeral3d/config.ts` (не в calculationUtils). Туда добавлено поле `wreathSkus?: string[]`.

### Ключевые файлы

| Файл | Роль |
|---|---|
| `components/AttributeRender.tsx` | Деривация конфига из сметы, маппинг SKU, вызов RitualSetPreview. Есть SVG-фоллбэк. |
| `components/visualizer/RitualSetPreview.tsx` | Рендер сцены: `SceneStage` (AI-фон + до двух венков на мольбертах). Есть старый `LayerStack` (2.5D-слои) как фоллбэк, если нет сцены. |
| `components/visualizer/sceneAnchors.ts` | Карта координат мольбертов по каждой сцене: `SCENE_EASEL_ANCHORS[sku] = {left,right}` (доля ширины). Плюс `WREATH_CENTER_Y=0.41`, `WREATH_HEIGHT=0.45`. |
| `components/funeral3d/config.ts` | Тип `AttributePreviewConfig` (+ `wreathSkus`). |
| `lib/calculationUtils.ts` | Каталог `AGENT_ATTRIBUTION_CATALOG`, типы `CatalogItem`/`EstimateItem`, `CatalogCategory`, `CATALOG_CATEGORIES`. |
| `app/agent/(app)/meetings/[meetingId]/quote/QuoteBuilder.tsx` | Конфигуратор сметы: категории атрибутики, добавление в смету, лимит венков = 2. |

### Наложение венков (текущая реализация)

- Позиция берётся из `SCENE_EASEL_ANCHORS[coffinId]`. `wreathIds[0] → левый мольберт`, `wreathIds[1] → правый`. Один венок → левый мольберт.
- Вертикаль/масштаб: центр по `WREATH_CENTER_Y`, высота `WREATH_HEIGHT` от высоты кадра; `transform: translateX(-50%)` центрирует по X мольберта; `drop-shadow` даёт контактную тень.
- Якоря получены детекцией тёмных вертикальных структур (мольберты чёрные) в полосе y∈[24%,56%]; выбросы (fch-2, fsr-6) поправлены вручную. Правый мольберт детектится надёжно, левый был на ~2% левее — добавлен сдвиг +0.015.

## 2. Активы и как они сгенерированы

### Сцены гробов — `public/visualizer/scenes/<sku>.jpg` (21 шт, все гробы каталога)

Список sku: fch-2, fh-2, fkl-6s, fkl-6t, fklv-6s, fko-6, fo-2, fs-4, fs-6, fsi-6, fsi-6b, fsi-6s, fsi-6t, fsn-4, fsn-6s, fsr-4, fsr-6, fv-2, fva-2, fvk-2s, fvp-2s.

Генерация — по одному изображению на гроб: пустой зал (база `public/telegram-cloud-document-2-5339499459736804779.jpg`) + каталожный гроб `public/catalog/coffins/<sku>.jpg` → фотореалистичная сцена, гроб во всю длину катафалка, два пустых мольберта в кадре. Зафиксированный промпт (RU): «Сделай такую же сцену с этим гробом. Тот же зал, ракурс и свет. Гроб почти во всю длину чёрного стола-катафалка, два пустых мольберта в кадре. Точно сохрани форму, цвет, глянец, резьбу и ручки этого гроба, не меняй дизайн. Фотореализм, 4:3.»

Два способа генерации:
- **Через браузер на подписке ChatGPT Plus** (использовался фактически): прикрепить гроб в чат, промпт, дождаться (~50–120с), скачать. Важно: скачивать сразу после прорисовки — подпись URL картинки истекает, иначе скачивается 45-байтовый JSON `{"detail":"Invalid signature..."}`. Полноэкранный редактор часто показывает alt-текст (не рендерит), но кнопка загрузки тянет файл; если пришёл JSON — перегенерировать и скачать быстро.
- **Через API-скрипты** (быстрее и надёжнее, требует ключ с биллингом): `scripts/catalog/generate_scenes_openai.py` (OpenAI `gpt-image-1`, `images.edit`) или `scripts/catalog/generate_scenes.py` (Gemini `gemini-2.5-flash-image`). Оба пропускают уже готовые сцены. Подписка ChatGPT Plus ≠ API-доступ.

### Вырезы венков — `public/visualizer/wreaths-cut/<sku>.webp` (7 шт, прозрачный фон)

sku: avtorskie, cvetopad, krest, standart-blue, standart-mix, standart-red, tricolor. Вырезаны из чистых белых карточек `public/catalog/wreaths/<sku>.jpg` через flood-fill белого фона (см. историю; сейчас чистые, полные, без обрезки верха). Чёрная «рюша» у standart-blue/mix — реальная траурная кайма венка, не артефакт. Файлы `orthodox-oval-*` в этой папке — мёртвые, каталог их не запрашивает.

### Пайплайн выреза каталога — `scripts/catalog/ai_matte.py`

Запускается на Mac (rembg/BiRefNet, opencv), не в песочнице (там нет весов модели и лимит 45с). Делает белые карточки `public/catalog/<cat>/<sku>.jpg` и прозрачные слои `public/visualizer/<cat>/<sku>.webp`. Боксы страниц PDF — в `scripts/catalog/{coffins,extras,wreaths}.json`.

## 3. Свой каталог агента (авто-вырез фона) — НОВОЕ, требует шагов установки

Идея: агент грузит фото своих товаров → платформа сама вырезает фон в браузере и ставит товар на белый фон → агент задаёт название/категорию/цену → товар доступен в смете наравне с базовым каталогом.

| Файл | Роль |
|---|---|
| `prisma/schema.prisma` | Модель `AgentCatalogItem` (id cuid, agentId→Agent, name, category, clientPrice, costPrice, description, imageData `@db.Text`, createdAt). Связь `catalogItems` добавлена в модель `Agent`. |
| `app/api/agent/catalog/route.ts` | `GET` (список товаров агента), `POST` (создать). Авторизация `getSessionFromRequest(req)` → `session.agentId`. Валидация категории/цены/размера картинки. Если таблицы нет — GET graceful отдаёт `{items:[]}`. |
| `app/api/agent/catalog/[id]/route.ts` | `DELETE` своего товара (async `params: Promise<{id}>`). |
| `components/agent/CustomCatalogManager.tsx` | Клиент: загрузка фото → `@imgly/background-removal` (ONNX/WASM, без ключей/оплаты) → белая карточка 4:5 (canvas, webp data URL) → форма name/category/price → POST; список с удалением. |
| `app/agent/(app)/catalog/my/page.tsx` | Страница «Мой каталог» (монтирует менеджер). Ссылка добавлена в шапку `app/agent/(app)/catalog/page.tsx`. |
| `app/agent/(app)/meetings/[meetingId]/quote/QuoteBuilder.tsx` | Фетчит `/api/agent/catalog`, мапит в `CatalogItem[]` (id `custom-<id>`, imageUrl = data URL) и подмешивает в `filteredCatalogItems`; добавляются в смету штатным `addCatalogItemToEstimate`. |
| `package.json` | Добавлена зависимость `@imgly/background-removal` (^1.5.8). |

Хранение картинок — data URL прямо в БД (`@db.Text`). В зависимостях уже есть `@vercel/blob` — для масштаба вырезы стоит перенести в Blob и хранить URL, а не base64.

## 5. Известные ограничения и риски (честно)

1. **Наложение венков — 2D-оверлей на фотосцене.** Даже при точной посадке на мольберт это плоская картинка на 3D-кадре: нет истинной перспективы/окклюзии/единого света. На части сцен левый венок подходит близко к краю и слегка перекрывает угол гроба. Это «хорошо», но не «неотличимо от фото».
2. **Якоря мольбертов** получены эвристической детекцией; два выброса правились руками. При перегенерации любой сцены её якорь надо пересчитать/проверить.
3. **Авто-вырез фона агента** зависит от качества фото (лучший результат — товар на однородном светлом фоне). Тонкая листва/сетка венков вырезается хуже гладких предметов.
4. **Картинки в БД как base64** раздувают строки; для сотен товаров нужен Blob/S3.
5. **Сборку/типы/линт ассистент не гонял** (нет доступа к билду в песочнице). Перед мержем прогнать обязательно.
6. Множественный выбор венков ограничен двумя только в UI (`QuoteBuilder.toggleCatalogItem`); визуализатор в любом случае показывает максимум 2 (`slice(0,2)`).

## 6. Что значит «по-настоящему bigtech» — план для следующего чата

Приоритет 1 — качество сцены с венками (устранить «наклейку»):
- **Вариант A (рекомендуется): генерировать венок прямо в сцену AI.** Пайплайн: базовые 21 сцены с ПУСТЫМИ мольбертами уже есть; для товара «венок» отдельно генерировать оверлей «венок на мольберте в этом зале» и/или собирать финальную сцену композицией на стороне модели. Комбинаторика гроб×венок велика (21×7=147) — решать через: (1) кэш по паре (coffin,wreath) с ленивой генерацией по факту выбора и сохранением в Blob; либо (2) генерировать один «слой венка на мольберте» на нейтральном фоне с фиксированной геометрией зала и композитить — но это опять оверлей.
- **Вариант B: настоящий 3D** (`components/funeral3d/*` уже заложен) — зал + катафалк + мольберты как сцена, гроб/венок как плоские билборды с корректной посадкой, тенями и DOF. Дороже, но даёт консистентность и интерактив (вращение, зум).
- **Вариант C: улучшить текущий оверлей** — перспективный warp венка под наклон мольберта, мягкая контактная тень на держателе, лёгкая цветокоррекция под свет сцены, окклюзия нижней части венка держателем. Дёшево, быстро, заметно лучше.

Приоритет 2 — свой каталог как продукт:
- Загрузка не только фото, но и **каталога документом** (PDF/изображение многостраничное): парсинг страниц (`pdfjs-dist`), выбор/кроп товаров рамкой, батч-вырез. Сейчас реализовано только по одному изображению.
- Хранение вырезов в **Vercel Blob** (уже в зависимостях) вместо base64 в БД; в модели держать `imageUrl`.
- Редактирование товара (не только создание/удаление), дубли-защита, сортировка, поиск.
- Ручная докрутка выреза (кисть/порог) на случай плохого авто-результата.
- Права/лимиты: сколько товаров на агента, модерация.

Приоритет 3 — инженерная строгость (обязательна для «без ошибок»):
- Zod-схемы на вход API (в проекте уже есть `zod`).
- Юнит-тесты на `derivePreviewConfigFromEstimateItems` и `previewIdsFromConfig` (текстовая эвристика хрупкая: определяет венок/гроб/крест по подстрокам — легко ломается на кастомных названиях агента). Кастомные товары агента сейчас определяются по названию — если агент назовёт венок «Композиция №5», он не попадёт в венки. Нужен явный `category`-путь вместо/в дополнение к текстовой эвристике.
- `next build` + `tsc --noEmit` + `eslint` в CI, скриншот-тест сцены.

## 7. Полезные факты окружения

- Авторизация агента в API: `import { getSessionFromRequest } from "@/lib/auth"` → `session.agentId` (Int). Prisma-клиент: `import { prisma } from "@/lib/prisma"`.
- `Agent.id` — Int autoincrement.
- `buttonClasses({ variant, size, className })` из `components/ui/Button`; варианты: primary|secondary|ghost|danger.
- Категории атрибутики в конфигураторе (порядок): Гробы → Венки → Постель / комплект в гроб → Кресты / таблички → Урны. «Урны» показываются только при `serviceType === "cremation"` (`visibleCategories`/`activeCategory` в QuoteBuilder).
- Одиночные категории (radio): Гробы, Постель / комплект в гроб, Урны (`SINGLE_CATEGORIES`).
