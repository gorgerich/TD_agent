# HANDOFF — «Тихий дом для агентов» (B2B)

Документ для продолжения работы в новой сессии (в т.ч. на другой машине). Прочитать
вместе с `prisma/schema.prisma`. Источник истины по B2C — репозиторий `gorgerich/frontend`
(read-only, **трогать нельзя**).

## Что это

B2B-платформа поверх существующего B2C-сервиса tihiydom.com (онлайн-организация похорон,
Москва/МО, ИП Пачулия). Сценарий: агент приходит к клиенту домой, на встрече клиент сам
собирает смету (агент направляет), подписание и оплата на месте.

## Решение по модели агента — НЕ ПОДТВЕРЖДЕНО собственником

Рабочая гипотеза — **внутренняя модель**: агент = представитель ТД, оплата идёт ТД,
ТД фискализирует и отвечает за качество. Альтернатива — маркетплейс (агент = внешний
исполнитель, как в текущей оферте). Эти модели несовместимы; от выбора зависят оферта,
кому идут деньги, кто формирует чек. **До письменного решения собственника заблокированы:**
оферта, агентский договор, реальная prod-миграция.

Структура данных при этом почти модель-агностична — меняется семантика (получатель Payment,
кто формирует чек), не форма таблиц.

## Бриф расходился с реальной схемой — верить коду, не пересказу

На старте был дан бриф, который врал по схеме. Факт (см. `gorgerich/frontend/prisma/schema.prisma`):
- `OrderHistory` — **не существует** (в брифе заявлен).
- `OrderStatus` enum — **не существует**. Реально `Order.status String @default("PENDING")`.
- `Payment` — **уже есть** (привязан к платёжному провайдеру: provider, providerPaymentId,
  confirmationUrl, webhookRaw). В B2B он **переиспользован**, не продублирован.
- `User.id` и `Order.id` — `Int @autoincrement`, не cuid. Все новые FK — `Int`.
- `Order.totalAmount` — копейки (Int), `Order.meta` — JSON строкой.

## Стек (факт, не бриф)

Next **16** (не 14), React 19, Prisma 5.22 (client сгенерирован), Tailwind 4, Vercel, БД PostgreSQL.
**Auth-библиотеки в проде НЕТ** (ни NextAuth, ни Clerk). Есть openai, resend, nodemailer.
WebSocket-библиотек нет.

## Решения по B2B-схеме (уже в `prisma/schema.prisma`)

- Новые модели: Agent, AgentTier, ClientLead, Meeting, Quote, QuoteVersion, Signature,
  Commission, Payout, AgentSession. Новые enum: AgentStatus, MeetingStatus, PaymentMethod,
  CommissionStatus, PayoutStatus, SignatureMethod.
- `Order.status` оставлен **String** — НЕ мигрируем на enum, его читает B2C-код (трогать нельзя).
  Новые допустимые значения документированы комментарием в схеме.
- Существующий `Payment` расширен полями method/isDeposit/fiscalUrl/fiscalSign/confirmedAt/meetingId.
- Все FK новых моделей — `Int`, единообразно с User/Order.
- `prisma validate` проходит после заполнения `.env` (DATABASE_URL + DIRECT_URL).

## Архитектурные решения

- **Разделение B2C/B2B — вариант B**: поддомен `agents.tihiydom.com`, общая БД,
  переиспользование `calculationUtils.ts`. B2B не индексируется (X-Robots-Tag + robots.txt).
- **Auth** — рекомендация Auth.js (NextAuth v5), роли из БД, раздельные сессии B2C/B2B.
  Сейчас `lib/auth.ts` — типизированная заглушка (`getAgentSession` возвращает null).
- **Co-browse** — НЕ screen-share (видео экрана с ПДн = обработка ПДн по ФЗ-152, тяжело и
  рискованно). Выбран вариант «зеркало сметы»: клиент по коду видит ту же смету, без курсора/звука.
  State синхронизируется как JSON, шифруется на уровне приложения.
- **Фискализация (54-ФЗ)** — облачная касса по API (ATOL Online/OrangeData) на ИП Пачулия;
  чек по СБП формируется по вебхуку, по наличным — электронный чек на телефон. BLOCKING-вопрос
  MVP: допустимость только электронного чека и «место расчёта» при выездном приёме налички —
  проверить у налогового консультанта.
- **Подписание** — ПЭП через SMS-код, фиксируется sha256-хэш PDF. Достаточность ПЭП для договора
  ритуальных услуг — проверить у юриста.
- **Оплата СБП** — счёт ТД (внутренняя модель), `Order` → PAID по вебхуку банка, не по показу QR.

## Жёсткие ограничения

- `gorgerich/frontend` (B2C) **не трогать** — read-only референс.
- **НЕ запускать `prisma migrate` против прод-БД** — она общая с B2C. Локально — отдельная dev-БД.
- ФЗ-152: ПДн клиента и умершего шифровать; логировать доступ агента; удалять co-browse state
  по `AgentSession.expiresAt`.

## Открытые блокеры (не техника — решения)

1. Письменное решение собственника по модели агента.
2. Налоговый консультант: фискализация выездных наличных (54-ФЗ).
3. Юрист: переписанная оферта, агентский договор, материальная ответственность, согласие ПДн.
4. Банк: эквайер СБП C2B на ИП, вебхуки.
5. Фактические закупочные цены (COGS) по позициям базовой сметы — без них юнит-экономика недостоверна.
