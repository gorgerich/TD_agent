# UX/UI аудит — кабинет агента «Тихий дом»

_Дата: 17.06.2026. Метод: ревью кода и дизайн-доктрины (`DESIGN.md`, `globals.css`, ключевые экраны и компоненты). Ограничение: dev-сервер в песочнице не запускается (`node_modules` собран под macOS), поэтому динамика (анимации, реальные состояния данных, отклик форм) проверяется на вашем превью. Все правки контраста проверены расчётом WCAG._

---

## Вердикт (без смягчения)

Премиса задачи «довести до уровня бигтеха» **частично неверна**. Дизайн-фундамент уже на этом уровне: `DESIGN.md` — это зрелая, дисциплинированная система «Quiet Depth v3» с прямыми референсами Linear / Mercury / Notion, 5-слойной системой поверхностей, шкалами теней/радиусов/типографики и анти-slop сводом. Подтверждение делом: **0 инлайн-hex-цветов на 79 компонентов** — это редкая дисциплина даже для финтеха.

Поэтому переписывать «стиль» — пустая трата времени и риск регресса. Реальный разрыв до Сбер/МТС-планки не в эстетике, а в трёх вещах: **доступность (WCAG AA), конформность собственной доктрине и полировка состояний/потока.** Ниже — приоритизировано, с доказательствами.

Топ-5 рычагов: (1) контраст вторичного текста и сумм ниже AA; (2) фокус-кольцо есть только в `<Button>`; (3) дрейф от доктрины (border на карточках, `transition: all`); (4) тяжесть конструктора сметы; (5) отсутствие единого паттерна пустых/ошибочных состояний на части экранов.

## Что уже на уровне бигтеха — не трогать

- **Токены и дисциплина.** Единый источник в `globals.css @theme`; 0 произвольных цветов в разметке. Семантика (success/warning/danger/info + soft), gold только для денег.
- **Глубина без «дутости».** 5 слоёв поверхностей, слоистые тени (ring + ambient + contact + `--hl-top`), отказ от жёстких рамок в пользу тени-кольца.
- **Закон плотности / анти-slop.** Прямой запрет россыпи пилюль, дублей заголовков, декоративных градиентов и текстур. Это и есть «когнитивная лёгкость», уже кодифицированная.
- **Моторика.** Шкала кривых и длительностей, `prefers-reduced-motion` гасит всё, запрет `transition: all` (см. P1 — на практике нарушается).
- **Состояния частично закрыты:** Skeleton используется в ~25 местах, пустые состояния — ~37 строк.

## P0 — доверие и доступность (планка финтеха = WCAG AA)

**1. Вторичный текст ниже AA.** `ink-3 #748d92` на белом = **3.52:1** (норма AA для текста — 4.5:1). А это именно строки «что дальше» и подписи — основной вторичный текст по закону плотности. На сером инпуте (`surface-2`) ещё хуже — 3.21:1.
→ Фикс: `ink-3 = #5a767c` (**4.86:1**, на surface-2 — 4.44:1). Тон почти тот же, читаемость проходит AA.

**2. Деньги ниже AA.** `gold #b4791f` = **3.69:1**. Это суммы и комиссии — важнейшие числа в продукте про доверие и прозрачность цены. Нечитаемые деньги = прямой удар по позиционированию.
→ Фикс: `gold = #936216` (**5.25:1**). Остаётся золотисто-янтарным, но читается.

**3. Фокус-кольцо только в `<Button>`.** `focus-visible` централизован в одном компоненте. Десятки кастомных `<button>` и кликабельных карточек (списки сущностей, чипы, карточки каталога — включая мой новый каталог) **без видимого фокуса** → навигация с клавиатуры невидима. Для финтеха это базовый барьер доступности.
→ Фикс: глобальное правило `:focus-visible` в `globals.css` (accent-кольцо + offset) на всех интерактивных элементах.

_Все три — глобальные, низкого риска, не требуют превью. Применены в этом проходе (см. конец)._

## P1 — конформность собственной доктрине (дрейф кода от `DESIGN.md`)

**4. `border-line` на карточках — 104 использования.** Доктрина: «Жёсткая рамка `border-line` на карточках устарела — структуру держит тень-кольцо». На практике карточки часто обведены рамкой → «коробочный», менее премиальный вид, двойной контур (рамка + тень). 
→ Фикс: пройтись по карточкам, снять border, оставить `shadow-soft`. Hairline — только разделители ВНУТРИ. (Требует превью — менять оптом вслепую нельзя.)

**5. `transition: all` — 11 случаев.** Прямой запрет доктрины (раздел «Моторика»: «только с явными свойствами»). Бьёт по предсказуемости и кадрам.
→ Фикс: заменить на явные `transform, opacity, background-color…`.

**6. Дрейф в моём новом каталоге.** Чипы категорий и серий я сделал border-пилюлями, а в системе для этого есть паттерн `td-segmented` (серый трек + белая активная пилюля + shadow-soft, iOS/Linear). Карточки используют `border-line`. Кнопка «в подборку» — кастомная, не из `<Button>`.
→ Фикс: привести каталог к `td-segmented`, `td-shell` без border, `<Button>`/`buttonClasses`. (Могу сделать сразу — файл мой, риск низкий.)

## P2 — когнитивная лёгкость и поток (CJM агента)

**7. Конструктор сметы — самая тяжёлая поверхность.** `QuoteBuilder.tsx` ~1300 строк, `QuoteBuilder.module.css` **2421 строки**, 5 шагов + 3D-конфигуратор + блок экономики + внешние расходы на одном экране. Риск перегрузки на главном рабочем экране агента.
→ Проверить на превью: фокус одного шага за раз, липкая сводка итога+маржи, прогресс без «степпер-шума» (доктрина запрещает прогресс-бары в строках, но в самом wizard сводка нужна). Кандидат на декомпозицию CSS-модуля.

**8. Единый паттерн состояний.** Skeleton и пустые состояния есть, но покрытие неровное (25 vs 79 экранов/компонентов). Нет подтверждения единого паттерна для **ошибки загрузки** и **состояния «нет связи»** (важно для мобильного агента в разъездах).
→ Свести к 3 переиспользуемым компонентам: `EmptyState`, `ErrorState`, `LoadingState` (Skeleton уже есть).

**9. Первое касание / онбординг.** Не подтверждён first-run: что видит агент с пустой воронкой (0 лидов / 0 встреч). Пустой дашборд без проводника = тихий отток.

**10. Мобайл.** `AgentBottomNav` есть — мобильный путь продуман. Проверить плотность таблиц/сметы на ширине ~380px (агент работает с телефона на выезде) на превью.

## CJM: лид → встреча → смета → комиссия

Поток собран и логичен (`leads → meetings → quote → commissions`). Точки трения для проверки на превью:
- **Лид→встреча:** сколько кликов до назначения; есть ли быстрое действие из строки лида.
- **Встреча→смета:** вход в конструктор — сразу ли видна «вилка» тариф / свой план (доктрина «две точки входа в одни данные»).
- **Смета→отправка клиенту:** превью клиентской `/co/[code]` сметы — единый материал с B2C (бумага `paper`) — сильный ход, проверить консистентность.
- **Каталог↔смета:** теперь связаны подборкой (этот спринт). Логичный мост; добавить состояние «подборка пуста» и счётчик в навигации.
